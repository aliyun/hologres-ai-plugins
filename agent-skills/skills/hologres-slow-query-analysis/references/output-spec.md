# 输出规范

精简主流程只引用本文件。组装最终 markdown 报告时按以下规则逐字执行。

---

## 1. 标准逐项模板（强制）

两条流程的每个诊断项都使用此骨架：

```
【诊断项名称】
- 指标口径：{统计口径说明}
- 关键结果：{核心数值或 Top 对象}
- 现象总结：{现象描述}
- 原因判断：{原因分析}
- 建议：{优化建议}
- 结论：{一句话总结}
```

当该诊断项涉及具体 SQL（TOP / 优先优化 / 错误分类）时，额外包含：

```
- 典型完整 SQL（含 query_id）：query_id={...}，SQL={完整 query 原文，不可截断}
```

---

## 2. 标题规则

- 实例级报告标题：**`Hologres 实例级整体慢 Query 诊断`**。
- 标题**不得**用「报告」字样。
- 单条 SQL 分析：**`Hologres 单条 SQL 慢因诊断 - {query_id}`**。

## 3. 分析人字段规则

- 「分析人」字段必须为执行诊断 SQL 的实际 `current_user`（如 `<current_user>`）。
- 不得硬编码 `QoderWork`、`AI助手` 等值。

## 4. 引擎类型规则（两处强制）

凡呈现 digest 聚合或单条最慢 SQL 排名处，同时呈现 `engine_type`：

- `engine_type` 为数组类型 → 任何聚合用 `engine_type::text`。
- **FixedQE（Fixed Plan）** SQL：频次高、单查询代价小；非慢 SQL 瓶颈。仅简述执行次数 + 总耗时。
- **HQE** SQL：主要分析负载。始终深入检查 扫描 / 内存 / CPU / 计划。
- **PQE** SQL：提示某算子未走 HQE。建议改写回 HQE。
- **PG** SQL：通常系统目录 / DDL。ANALYZE 类后台工作在此正常；用户数据查询落到 PG 异常。

---

## 5. 必含输出项 — 实例级流程

最终 markdown 至少含这 12 节：

1. 分析时间范围
2. SQL 总量、成功数量、失败数量总结
3. 慢 SQL 总体情况总结
4. TOP 慢 SQL 总结
5. TOP 总耗时 SQL 模板（按 digest）总结
6. 主要用户 / 应用总结
7. 主要涉及表总结
8. 资源瓶颈总结
9. 错误 SQL 总结（按 SQLSTATE 分类）
10. 优先优化清单总结（含 query_id 与完整 SQL 原文）
11. 每项诊断结果总结
12. 最终优化建议总结

## 6. 必含输出项 — 单条 SQL 流程

1. `query_id`
2. SQL 原文（不可截断）
3. 执行耗时总结
4. 扫描与返回特征总结
5. 资源消耗总结
6. 读写表总结
7. 执行计划摘要总结
8. 慢因总结
9. 优化建议总结
